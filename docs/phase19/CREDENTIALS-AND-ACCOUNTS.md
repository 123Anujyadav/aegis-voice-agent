# Credentials, external accounts and costs: register

- **As of:** 2026-10-24, `main` at `ae094ef`.
- **What this lists:** every credential, external account or paid service the
  code needs, with:
  - the exact names the code reads, or names marked **proposed** where
    nothing reads them yet;
  - what each one blocks, and what can continue without it.
- **How the names were verified:** each name is `<service prefix>_<env tag>`.
  - `platform.LoadConfig(&cfg, "CS_IDENTITY")` and `"CS_EDGE_API"` supply the
    prefix.
  - The field tags supply the rest: `services/go/identity/internal/bootstrap`
    (`bootstrap.go`, `runtime.go`) and `services/go/edge-api/internal/auth`
    (`auth.go`).
  - `…_ENVIRONMENT` comes from the platform's shared service configuration.
- **Nothing here is provisioned.** No credential, account or paid service has
  been created, and none may be without the owner's (and, for
  infrastructure, SRE's) authorisation.
- **Never in chat or Git.** Every secret is a file mounted from a Kubernetes
  Secret (the `*_FILE` names) or a workload identity.
- **Costs** are stated only where verified. "Unverified" means it must be
  checked against the provider's current pricing before anything is enabled.

**Kinds used below:**

| Kind | Meaning |
|---|---|
| **Secret** | Must stay confidential: a mounted file, never in configuration, logs or Git |
| **Config** | Not secret: ordinary deployment configuration |
| **Identifier** | A public or project identifier (a package name, project number, certificate digest) |
| **Proposed** | A name documented for future code. Nothing reads it yet. |
| **Not integrated** | The service is not used by any code yet, only by an interface or a mock |

## 1. Self-generated keys and secrets (no external account)

These are generated by SRE and mounted as files. They incur **no external
cost**, and they block **staging and production only**: local development and
CI generate test keys inside the tests.

| Name (read by the code) | Kind | Service | Holds |
|---|---|---|---|
| `CS_IDENTITY_ACCESS_TOKEN_PRIVATE_KEY_FILE` | Secret | identity | The Ed25519 private key that signs access tokens. Rotation: `docs/runbooks/access-token-signing-key-rotation.md` (never exercised). |
| `CS_IDENTITY_HMAC_SECRET_KEY_FILE` | Secret | identity | The HMAC key: OTP and refresh-token hashes, pseudonyms, subscriber ids. It has no rotation path until ADR-0030 is implemented. |
| `CS_IDENTITY_DATABASE_DSN_FILE` | Secret | identity | The PostgreSQL DSN (`verify-full`, explicit CA) |
| `CS_IDENTITY_ACCESS_TOKEN_KID`, `CS_IDENTITY_ACCESS_TOKEN_ISSUER`, `CS_IDENTITY_ACCESS_TOKEN_AUDIENCE` | Config | identity | The key id, issuer and audience |
| `CS_IDENTITY_ENROLLMENT_CANONICAL_URL`, `CS_IDENTITY_REFRESH_CANONICAL_URL` | Config | identity | The canonical `htu` URLs that clients must sign |
| `CS_EDGE_API_ACCESS_TOKEN_PUBLIC_KEY_FILE` | Config, mounted | edge-api | The active verification key (public) |
| `CS_EDGE_API_ACCESS_TOKEN_PREVIOUS_PUBLIC_KEY_FILE`, `CS_EDGE_API_ACCESS_TOKEN_PREVIOUS_KID` | Config | edge-api | The previous key, during rotation only |
| `CS_EDGE_API_ACCESS_TOKEN_KID`, `…_ISSUER`, `…_AUDIENCE`, `CS_EDGE_API_PUBLIC_ORIGIN`, `CS_EDGE_API_ENVIRONMENT` | Config | edge-api | Configuration |
| `CS_EDGE_API_DATABASE_DSN_FILE` | Secret | edge-api | The PostgreSQL DSN for the replay store |

## 3. Not needed today

The speech and voice packages are provider-agnostic. No vendor SDK or API key
is in the code, and development uses local models (Whisper, Piper, Ollama).
A hosted speech or LLM provider needs its own row here when one is chosen.

## 4. How to keep this current

Add a row the moment code starts to depend on a new credential, in the same
PR. Then:
- **Proposed** becomes a real name when the code that reads it merges.
- **A cost** leaves "unverified" only with a reference to the provider's
  current pricing page.
