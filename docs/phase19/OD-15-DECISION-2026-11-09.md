# Owner decision OD-15: identity with no configuration in staging and production (2026-11-09)

- **Decision:** approved by the owner on 2026-11-09: **option A**, on the read-only technical review of the same day.
- **Decision ID:** OD-15 ([`ROADMAP-INVENTORY.md`](ROADMAP-INVENTORY.md) §3.3), for production-readiness finding **F12** ([`PRODUCTION-READINESS.md`](PRODUCTION-READINESS.md) §4, §4.1). The earlier analysis is [`F11-F12-IDENTITY-SIGNALS-AND-READINESS.md`](F11-F12-IDENTITY-SIGNALS-AND-READINESS.md) §2.
- **Classification:** **an ordinary owner decision, not high-risk.** The owner classified it so; it changes no Accepted ADR, frozen invariant or trust boundary. **No independent review (OD-12) is required.**
- **Implemented in:** #260.

## The problem (F12)

With no `CS_IDENTITY_*` activation variable, identity boots **inactive**:
- it binds no application port and serves no route;
- its only readiness check is non-critical, so `/readyz` answers **200** (`degraded`).

**The consequence:** a staging or production pod that lost its identity configuration would pass its readiness probe. Its rollout would succeed while it served nothing. edge-api, by contrast, refuses to start without its configuration.

## The decision

1. **In staging and production, an identity with no activation configuration exits non-zero before binding any port.**
2. **Development, an unset tier and an empty tier keep the existing inactive behaviour.**
3. **Partial and invalid configurations keep their existing validation behaviour.**
4. **Accepted limitation:** a missing `CS_IDENTITY_ENVIRONMENT` defaults to `development`. So a pod that lost the tier together with its activation variables is **not** caught by option A.
5. **Mitigation:** deployments set `CS_IDENTITY_ENVIRONMENT` explicitly in the **pod specification**, independently of the Secret that holds the activation credentials ([`INTERNAL-TESTING-SETUP.md`](INTERNAL-TESTING-SETUP.md) C1, C3).
6. **Classification:** an ordinary owner decision, not high-risk; no OD-12 independent review.

## What changes, and what does not

**Changes:**
- **The refusal:** `services/go/identity/cmd/server/identity.go`, in `configureIdentity`'s inactive branch. When `ServiceConfig.Environment` is `staging` or `production`, it returns `errIdentityRequired`: "identity is not configured: staging and production require the CS_IDENTITY_* activation variables". The message is fixed and carries no value or path.
- **The exit:** `run()` returns the error before `svc.Run`, so neither the health port nor the application port is bound. `main` prints `FATAL: identity: …` and exits with code 1.
- **Documentation:** the activation contract's documentation in `internal/bootstrap/runtime.go` says the same.

**Unchanged:**
- **Code not touched:** `packages/go/platform`, the `bootstrap` activation logic, edge-api, the PostgreSQL TLS policy, authentication, DPoP, tokens, cryptography and every deployment manifest.
- **Other commands:** `migrate`, `version` and `signing-key-fingerprint`, which do not configure identity.
- **Valid configuration:** a complete, valid configuration is unchanged in every tier.

| Tier (`CS_IDENTITY_ENVIRONMENT`) | No activation variable | Partial or invalid | Complete and valid |
|---|---|---|---|
| unset, empty or `development` | inactive skeleton: `/healthz` 200, `/readyz` 200 "identity inactive" (unchanged) | `ErrInvalidConfig`, exit 1 (unchanged) | active (unchanged) |
| `staging` or `production` | **exit 1 before binding any port** (new) | `ErrInvalidConfig`, exit 1 (unchanged) | active (unchanged) |

## Tests (#260)

**`identity_test.go`:**
- the inactive case for each of `""`, `development`, `staging` and `production`;
- a complete configuration reaching construction in every tier;
- partial and invalid configurations keeping `ErrInvalidConfig` in every tier, with no value or path in the error.

**`startup_process_test.go`:** the service re-run as a child process.
- `staging` and `production` exit with code 1 and the FATAL line, and neither port ever answers.
- Unset, empty and `development` serve `/healthz` 200 and `/readyz` 200 "identity inactive", with no application port.

**`tools/scripts/image-smoke.sh`:**
- The built image keeps the no-tier inactive check.
- With `CS_IDENTITY_ENVIRONMENT` set to `staging`, and then to `production`, it must exit non-zero within 30 s with the configuration-required error, never answering `/readyz`.

**Mutation checks:**
- With the refusal disabled, the inactive-tier unit test and the process test fail.
- An image built that way fails the smoke check.
